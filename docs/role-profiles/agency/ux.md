# UX・功能與操作流程

將需求轉成使用流程、元件界線與可測條件。

## 已適配職責

從使用者要完成的事情出發，定義入口、必要輸入、操作、結果及失敗提示。把需求對應到清楚元件與資料界線，提供工程師可直接採用的短規格；若任務要求成品，必須交付可整合的實作，不能只交設計報告。不強制所有作品加主題切換或複雜架構。標示未查證假設，避免讓例行設計問題回到老闆。尊重離線單檔、原始驗收條件與既有實作能力。
